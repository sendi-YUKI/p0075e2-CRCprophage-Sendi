# 正式细菌参考集合：选了哪些genome，Jinlong接下来如何处理

目前已经整理好**1,931份细菌参考基因组候选**。这份清单用于正式项目的下载和质量核查；最终纳入多少份genome、多少个独立菌株、覆盖多少个物种，要由Jinlong完成序列质控和分类核查后确定。

Jinlong可以从[候选详细清单](preselected.tsv)、[下载清单](download_manifest.tsv)和[带版本的组装编号列表](download_accessions.txt)开始，三份文件的accession及顺序一致。候选清单已经完成公共元数据筛选，但不代表每份序列已下载、已通过统一QC，或已完成序列相似度和系统发育核查。

## 1. 这些细菌参考基因组在项目中有什么作用

参考基因组为prophage提供可追溯的细菌背景。正式分析会从这些基因组中提取病毒区段，保存其宿主分类、原始坐标和邻近基因，再与患者宏基因组中发现的病毒共同分析。参考端可以帮助解释宿主、整合结构、菌株或谱系分布，并为后续寻找可培养对象提供线索。

参考集合覆盖CRC富集、耗竭或对照关联，以及疾病方向尚不明确但有生态或机制价值的宿主。具体genome可以来自不同临床来源；患者层面的CRC与对照比较由正式宏基因组队列承担，参考菌株的疾病来源需要单独依据可靠元数据判断。

## 3. 为什么选这些宿主，每种为什么不是相同数量

物种范围先根据文献和宿主生态确定，包括反复CRC富集、对照关联或耗竭的宿主，以及需要解释分类或生态背景的其他宿主。公开资源较少时，尽量保留符合条件的记录；资源较多时，按各宿主的候选数量预算，从不同BioProject、地区、采样体位和现有种标签中轮流选取，减少单一研究来源占据全部名额。

同一来源层内综合考虑人肠道来源、其他人来源和组装质量，并保留有分类参考价值的类型株。候选数量预算用于控制资源投入和覆盖范围，不代表患者疾病比较的统计功效。地区字段可能指提交机构而非真实采样地，正式分析还需核实。

## 4. 元数据筛选用了什么规则，哪些还需要重新核查

公共元数据的常规筛选起点是：报告完整度≥90%、污染≤5%、组装片段数（contigs）≤200。201–500条contig的记录放入备用，超过500条不进入主预选。公共质量指标缺失的记录可以条件保留，但后续仍需要实际序列QC。

部分完整组装或类型株有结构、分类参考价值，但公共CheckM指标存在警告。本次对其中81份记录作条件预选，交给Jinlong重新核查：对已有指标按完整度至少70%、污染至多15%、contigs≤200判断；个别缺失指标保留待查，不能视为已满足该项条件。**70%／15%是这部分候选暂留复查的条件，并非正式参考的通用合格门槛。** 最终按统一序列QC结果判断实际污染、完整度和去留。质控方法可参考[CheckM2](https://pubmed.ncbi.nlm.nih.gov/37500759/)。

明确的分类冲突列入待查；NCBI的`Inconclusive`表示该项检查尚不能定论，需要结合其他证据判断。原始提交名称、历史名称和序列核查后的最终名称分别保存，Fusobacterium和Faecalibacterium尤其需要核对。公共记录的有效状态也要检查：被标记为`suppressed`的RefSeq不直接优选；若使用其仍为`current`的配对GenBank组装，应保留更换依据及对应关系。参见[NCBI状态说明](https://www.ncbi.nlm.nih.gov/datasets/docs/v2/data-processing/policies-annotation/genome-processing/version-status/)。

## 5. 如何理解菌株的来源和疾病标签

表中的疾病关联方向描述的是文献所支持的宿主背景；每份genome的真实来源另行记录。大多数公开分离株缺少可靠疾病标签，缺失信息保留为`unknown`。不能仅凭“口腔”“粪便”或“肿瘤”等采样信息推断其适合进入CRC／非CRC病例对照比较。

当前候选表的菌株疾病比较资格统一暂记为`false`，表示尚未确认有足够可靠且可比的临床来源。Jinlong核查后，只有确实具备相应来源证据、体位和研究背景可比的子集，才考虑开展这一比较；其他参考仍可用于宿主结构、谱系和功能解释。

## 6. Jinlong接下来如何下载、质控和确定正式清单

在含有`download_accessions.txt`的目录中，用NCBI官方Datasets工具执行以下模板，并记录实际工具版本：

```bash
datasets download genome accession --inputfile download_accessions.txt --include genome --dehydrated --filename reference_candidates.zip
unzip reference_candidates.zip -d reference_candidates
datasets rehydrate --directory reference_candidates
```

逐accession的下载命令也在[下载清单](download_manifest.tsv)中。工作目录、并行、缓存和重试由Jinlong按执行环境确定；命令依据见[NCBI Datasets下载文档](https://www.ncbi.nlm.nih.gov/datasets/docs/v2/reference-docs/command-line/datasets/download/genome/)。按固定版本下载，所需版本不可用时记录失败与替换决定，不能静默改成latest。下载失败单列，不能计为QC排除或菌株不存在。

逐文件保存下载状态、实际字节数、官方校验文件及本地SHA256。目前候选表中的官方MD5和大小尚未逐FASTA取回，相关占位字段不表示文件已验证。

如果已有可用FASTA，可以核对其带版本的accession、来源和SHA256后复用。配对GCA/GCF、同BioSample的不同组装和不同版本，都需要确认实际序列及替换关系，不能仅凭名称相近就视为同一文件。

下载后统一核查完整度、污染、contig/N50、分类、同株别名及明显重复；固定实际使用的NCBI/GTDB版本、ANI方法、QC工具和数据库版本。记录短读碎片化对prophage调用的影响，并重查条件保留的结构锚点及公共质量指标缺失的记录。正式主要参考建议优先使用完整度≥90%、污染≤5%的组装，最终工具、阈值组合和例外由Jinlong明确记录。

为每条候选填写`final_included`、`excluded`、`replaced`或`review`及理由。正式冻结表至少包含参考ID、taxon、strain/别名、accession.version、BioSample/Project、实际来源、分类版本、QC工具/库版本、完整度/污染/碎片化、FASTA路径别名、SHA256、参考角色和纳排/替换理由。最终种数、独立菌株数和genome数分别从冻结表计算。

这里的“冻结”是确定本轮联合分析实际使用哪一版参考，并保存准确编号、序列校验和纳排理由。后续仍可更新，但要记录新版本及对下游分析的影响。具体交付要求见[正式研究各阶段交付与冻结](../../04_deliverables/交付清单与表字段.md)。
