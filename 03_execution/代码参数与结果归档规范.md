# 代码、参数与结果：怎样留下可理解的记录

## 一次真实运行的六件事

1. 实际输入清单及SHA256；数据用逻辑ID和相对路径索引。
2. 自写/修改代码及Git commit，工作流入口、模块和依赖。历史代码仅作参考；新工作流以Jinlong代码为准。
3. 生效配置的完整导出，包括默认值、命令行覆盖和环境/容器摘要；工具版本、数据库版本/哈希分别保存。
4. 完整命令与run ID、时间、线程/内存请求和实际消耗、退出码/状态、失败与重试。不要只记Slurm申请而称实际峰值。
5. 关键输出文件、哈希、行数及ID关系；缺失、零值和失败状态分开。
6. 图/表的源数据、生成脚本、参数入口与生成命令；每张图有figure_id，可从图回到输入和运行记录。

## 建议目录

```text
config/          实际生效配置和数据库锁定
workflow/        自写/修改代码与环境说明
manifests/       输入身份、纳排、文件校验
run_records/     命令、trace、日志摘要、失败重试
results/         关键结构化表与统计输出
figures/         PNG/PDF/SVG和source_data
reports/         Methods、当前状态、下一步
data_index/      大文件逻辑位置与校验
```

可直接导出Jinlong现有pipeline的等价记录，无需为本项目搭建另一套手工系统。小文件回传研究者并提交Git；大序列/BAM/数据库留服务器，不在两个结果目录反复复制大型临时输出。

## 研究者怎样从图找到代码和参数

先读实际填写的ACTUAL_WORKFLOW，了解每步目的、输入、工具和输出。以figure_id在figure_provenance中找到图源表、脚本、配置和input_run_ids；再按run_id到run_records查完整命令、生效配置、代码commit、输入校验及运行状态。工具与数据库版本从software_database查，实际参数从actual_parameters及所指配置文件查，大文件按large_file_index中的逻辑ID定位。

从图回到实际执行的对应关系应为：图 → 图源数据 → 生成脚本/命令 → run_id → 输入与生效配置。方法决策表说明为什么选择某项规则；实际配置和运行记录说明该次真正使用了什么。建议值、待定项和未运行模板分别保留原状态。

## 怎样改参数，哪些需要重跑

临床身份/reads规则改变：重新计算受影响供者及其下游。参考QC或prophage调用改变：更新实例并重新构目录；如果目录/代表改变，则所有需要该目录的定量和统计重算。仅检出广度改变：若保留足够的逐位点/深度统计，可从相同映射重新形成状态与统计；若过滤影响read归属，应重算对应计数。仅统计模型改变：固定测量矩阵后重跑模型和图。仅图样式改变：从源数据重画，不重组装或映射。

例如修改pilot曾使用的75%检出广度，先读[决策表D19](Jinlong_方法与参数决策表.md)中的分母、位点深度和比对过滤，并定位实际配置键。仅调整广度阈值且已保存足够测量量时，可重算状态与统计；改变MAPQ或多重比对规则时，需要重算read归属和下游。新增正式参考若改变目录，应创建新目录版本并重算受影响测量，不能把新对象的几列直接拼入旧矩阵。

[复制候选重画脚本](tools/redraw_replication.py)可直接读取已打包底表生成新图，无需访问原服务器；它是从图源表重画的最小例子。已有11张图的代码与源数据保存在05_existing_results中。绘图样式的调整不改变原始分析结果。

## 最少模板

| 用途 | 填写或导出的位置 |
|---|---|
| 关键方法选择及理由 | [方法与参数决策TSV](Jinlong_方法与参数决策表.tsv) |
| 实际流程及步骤依赖 | [ACTUAL_WORKFLOW](templates/ACTUAL_WORKFLOW.template.md) |
| 每次运行的实际参数 | [actual_parameters](templates/actual_parameters.template.tsv) |
| 命令、配置、资源、状态与失败重试 | [run_records](templates/run_records.template.tsv) |
| 工具和数据库版本、来源及校验 | [software_database](templates/software_database.template.tsv) |
| 图、源表、脚本与运行对应 | [figure_provenance](templates/figure_provenance.template.tsv) |
| 大文件逻辑位置、校验、保存及重建 | [large_file_index](templates/large_file_index.template.tsv) |

身份、参考和目录的正式表及freeze_id使用[交付目录中的模板](../04_deliverables/交付清单与表字段.md)。其余状态、纳排和结果索引模板按实际流程需要选用，等价workflow导出记录同样可用。模板字段是记录要求，真实值来自新工作流；无需手工复写全部CLI。

## 保存与清理

保留最终参考FASTA、患者组装、prophage区段/侧翼/坐标、关键BAM及索引、基因和系统表、目录成员、过滤前后统计、关键日志、代码配置。大文件位置使用可访问的数据根，由Jinlong与研究者确定。公开GitHub可保存代码、表图和安全的配置记录，内部连接信息通过私下安全渠道交接。可再生工具临时文件按清理清单删除，记录如何重建；没有备份就如实写没有备份。
